# CONTEXT.md 文档规范格式

## 文档结构
```md
# {业务上下文名称}

{用一到两句话说明该上下文的业务范围与存在意义}

## 业务术语词典

**Order（订单）**:
对该术语的简短释义，一两句话为宜
_禁用替代词_：Purchase（采购单）、transaction（交易）

**Invoice（发票）**:
商品交付后发给客户的收款凭证。
_禁用替代词_：Bill、payment request（付款申请）

**Customer（客户）**:
提交订单的个人或企业主体。
_禁用替代词_：Client、buyer（买家）、account（账户）
```

## 编写规则
- **统一标准词汇**：同一业务概念若存在多种叫法，选定最优标准词，其余同义词统一列入`_禁用替代词_`。
- **释义精简凝练**：每条释义最多两句话，只定义概念本身是什么，不描述它的行为、功能。
- **仅收录本业务域专属术语**：通用编程概念（超时、错误类型、工具类设计模式）即便项目大量使用也不录入。新增术语前先判断：该概念是否为本业务上下文独有？只有独有概念才允许写入。
- **术语按需分组**：若术语可自然划分归类，使用二级标题分组；所有术语归属同一业务领域时，平铺列表即可。

## 单业务域仓库 / 多业务域仓库区分规范
**单业务域（绝大多数仓库）**：仓库根目录仅存放一份`CONTEXT.md`。

**多业务域**：仓库根目录新建`CONTEXT-MAP.md`，用于罗列所有业务上下文、文件路径与域间依赖关系：
```md
# 业务上下文总览映射

## 所有业务域
- [订单域](./ordering/CONTEXT.md) — 接收并跟踪客户订单
- [账单域](./billing/CONTEXT.md) — 生成发票、处理收款
- [履约域](./fulfillment/CONTEXT.md) — 管理仓库拣货与物流发货

## 域间依赖关系
- **订单域 → 履约域**：订单域发布`OrderPlaced`（下单完成）事件，履约域订阅事件并启动拣货流程
- **履约域 → 账单域**：履约域发布`ShipmentDispatched`（发货完成）事件，账单域订阅事件生成发票
- **订单域 ↔ 账单域**：共用`CustomerId`客户编号、`Money`金额基础数据结构
```

技能自动识别仓库结构逻辑：
1. 若存在`CONTEXT-MAP.md`，读取该文件获取全部业务上下文
2. 仅根目录存在`CONTEXT.md`，判定为单业务域仓库
3. 两者均不存在时，待第一个业务术语敲定后，再懒创建根目录`CONTEXT.md`

多业务域场景下，自动判断当前讨论内容归属哪个业务域；无法判定时主动向用户确认。
