# Change 文档规范

`change.md` 与对应 Domain 或 Workflow 放在同一目录，按时间追加已发生的语义变化。它不替代当前模型；读者应从 Domain/Workflow 获取现状，从 change 了解演进历史。

首次创建领域文档、排版调整和不改变语义的文字修正不记录 change。

## 标准模板

```md
## YYYY-MM-DD：变更标题

**变更原因**：触发变化的业务需求、缺陷或约束。

**语义变化**：

- 新增、修改或废弃的能力、术语、关系、规则、状态、事件或失败语义；
- 受影响的规则编号与原行为/新行为；
- 对外契约和兼容性影响。

**迁移与影响**：需要的数据迁移、消费者升级、回滚限制；没有则写“无”。

**关联**：相关 ADR、Domain、Workflow、spec 或实现位置。
```

保持简洁，但复杂变化必须写清原因、前后语义和兼容性。不得把讨论过程、未采纳方案或开放问题写入 change；这些分别属于 Discovery 或 ADR。
