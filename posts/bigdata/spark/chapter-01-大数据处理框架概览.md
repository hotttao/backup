# 第一章：大数据处理框架概览

> 本章定位：建立理解 Spark 内部执行机制的系统地图。重点不是记 API，而是理解一个大数据应用如何从用户代码变成集群上的任务。

## 1. 本章核心结论

大数据处理的本质，是把一个数据密集型应用拆成可以在多台机器上并行执行的任务，并由框架负责数据分区、任务调度、资源管理、故障恢复和物理执行。

Spark 相比早期 Hadoop MapReduce 的关键进步，可以概括为：

1. 用更通用的数据操作符表达复杂的数据处理流程。
2. 用 RDD 和依赖关系描述计算逻辑。
3. 把逻辑流程组织成 DAG，再切分为 stage 和 task。
4. 支持将可复用的中间结果缓存到内存，适合迭代计算和交互式分析。

## 2. 为什么需要大数据处理框架

大数据通常具有“4V”特征：

- Volume：数据量大
- Variety：数据类型多样
- Velocity：产生和处理速度快
- Value：数据蕴含较高价值

传统关系数据库和数据仓库分别擅长 OLTP 与 OLAP，但在数据规模持续增长时，会遇到扩展性和处理效率问题。大数据框架通过分布式存储、数据并行和横向扩展来解决这一问题。

## 3. 大数据框架的发展脉络

### MapReduce/Hadoop

MapReduce 采用“分治—聚合”的思想：先把数据切分并并行处理，再按照 key 汇聚结果。Hadoop 对相关分布式存储和计算思想进行了开源实现，逐渐形成完整生态。

### Dryad

Dryad 使用 DAG 表达任务流程，相比固定的 Map—Shuffle—Reduce 流程更加灵活。

### Spark

Spark 重点优化了内存计算和迭代式处理。它允许缓存可复用数据，并在内存中完成更多中间数据处理，从而减少重复的磁盘 I/O。

## 4. MapReduce-like 编程模型

抽象地看，MapReduce 的处理流程是：

```text
map:    <K1, V1> -> 多个 <K2, V2>
reduce: <K2, 多个 V2> -> 多个 <K3, V3>
```

以 WordCount 为例：

1. 输入文件被切成多个分块。
2. map 对每行文本分词，产生 `<word, count>`。
3. Shuffle 按 word 对中间结果重新分区、传输和聚合。
4. reduce 汇总同一个 word 的多个 count。

这个模型的优点是简单、易于并行化；局限是固定流程表达能力有限，复杂 join、排序和多阶段计算不够自然。因此 Spark 提供了 `flatMap`、`groupByKey`、`reduceByKey`、`cogroup`、`join` 等更通用的操作符。

## 5. 一个大数据应用由什么组成

可以把应用抽象为：

```text
应用 = 输入数据 + 用户代码 + 配置参数
```

### 输入数据

批处理数据通常预先存储在 HDFS 等分布式存储中，并被切分为多个分区；流处理数据则可能来自 Socket、Kafka 等，以微批或连续数据流进入系统。

数据读取经常是性能瓶颈，因此系统会通过缓存、内存分布式存储和数据本地性等手段减少磁盘和网络 I/O。

### 用户代码

用户可以直接编写底层转换逻辑，也可以使用 SQL、机器学习库或图计算库，由高层系统自动生成底层执行流程。

在 Spark 中，Driver 程序负责组织应用运行，可以生成或广播数据、提交计算、收集结果，并在 Driver 端完成最终汇总。真正的数据处理通常发生在 Executor 上的 task 中。

### 配置参数

配置大致分为两类：

- 资源类：Executor 数量、CPU、内存、缓冲区大小、JVM 堆大小等。
- 数据流类：分区函数、分区数量、数据分块大小等。

配置会直接影响并行度、网络传输、内存压力、数据倾斜和执行时间。配置调优不能脱离数据规模、数据分布和算子特征单独讨论。

## 6. 大数据处理框架的四层结构

这是本章最重要的系统视角：

```text
用户层
  ↓
分布式数据并行处理层
  ↓
资源管理与任务调度层
  ↓
物理执行层
```

### 6.1 用户层

用户准备输入数据、编写代码并设置配置。代码可以是手写的，也可以由 SQL 或高层库转换生成。

### 6.2 分布式数据并行处理层

这一层把用户代码转换为可并行执行的计算结构。

Hadoop MapReduce 的流程相对固定，通常直接形成 map 阶段和 reduce 阶段。

Spark 则分两步：

1. 根据算子和数据依赖生成逻辑处理流程。
2. 根据依赖关系将逻辑流程切分为 stage，再为每个 stage 生成 task。

Spark 中，输入数据和中间数据统一抽象为 RDD。RDD 包含多个 partition，RDD 之间通过依赖关系连接，整体形成 DAG。

这里要区分：

- RDD：数据及其分区的抽象。
- DAG：RDD 与依赖关系形成的逻辑计算图。
- Stage：可以在一个阶段内连续执行的一组计算。
- Task：处理某个 partition 的最小执行单元。

### 6.3 资源管理与任务调度层

大数据集群通常采用 Master-Worker 结构：Master 管理应用和资源，Worker 执行具体任务并汇报状态。

资源管理器负责回答“应用能获得多少资源”；任务调度器负责回答“哪个 task 在哪个节点、什么时间运行”。常见策略包括 FIFO 和 Fair。

Spark 可以运行在 Standalone、YARN、Mesos 等环境中。一个重要区别是：Hadoop MapReduce 往往为 task 启动独立 JVM，而 Spark 通常预先启动 Executor JVM，再在其中以线程方式运行多个 task。这会带来更高的复用效率，也意味着多个 task 会共享 Executor 的内存。

### 6.4 物理执行层

物理执行层真正启动和运行 task。Spark 的一个 job 可以包含多个 stage，stage 之间按照 DAG 的依赖顺序执行。

Task 的内存消耗主要来自三部分：

1. 框架产生的中间数据，例如 Shuffle 缓冲区。
2. 框架缓存的数据，例如 `cache()` 保存的 RDD。
3. 用户代码产生的中间对象和计算结果。

这也是 Spark 调优中经常出现 OOM、GC 过长、Shuffle 溢写和数据倾斜问题的根源。

## 7. Spark 与 Hadoop MapReduce 的关键差异

| 维度 | Hadoop MapReduce | Spark |
|---|---|---|
| 流程表达 | 以 Map—Shuffle—Reduce 为核心 | 通过算子和 DAG 表达多阶段流程 |
| 中间数据 | 更依赖磁盘 | 可缓存到内存，也会按需溢写 |
| 任务组织 | map task / reduce task | stage / task，不严格区分 map 或 reduce |
| 进程模型 | task 常对应独立 JVM | Executor JVM 中运行多个 task 线程 |
| 适合场景 | 稳定的批处理流程 | 迭代计算、交互式分析、复杂多阶段计算 |
| 容错思路 | 失败 task 重新执行 | 基于数据依赖重新计算丢失分区 |

## 8. 容错机制

分布式系统必须考虑节点宕机、网络异常、磁盘损坏、框架 Bug 和用户代码错误。

常见的基础策略是：某个 task 失败后，在其他节点重新运行。但这种方式无法解决所有问题，例如配置错误、代码逻辑错误或持续性的内存溢出，重试只会重复失败。

因此，大数据系统还需要：

- 记录数据依赖，定位出错路径；
- 记录中间数据，支持调试和回溯；
- 关联数据量、配置和内存消耗，诊断 OOM；
- 在资源不足时溢写、暂停或调整执行策略。

理解 Spark 时要特别注意：容错不是“所有数据都永久保存”，而是利用数据来源、转换关系和必要的持久化机制，在故障后恢复计算结果。

## 10. 面向面试的高频问题

### Q1：Spark 为什么比 MapReduce 快？

不能简单回答为“因为 Spark 使用内存”。更准确的回答是：Spark 通过 DAG 表达多阶段计算，并允许复用的数据驻留内存，减少不必要的磁盘 I/O；同时 Executor JVM 可复用，降低频繁启动进程的成本。但当数据无法放入内存、发生大量 Shuffle 或数据倾斜时，Spark 也可能很慢。

### Q2：RDD、Stage、Task 分别是什么？

RDD 是分区数据及其依赖关系的抽象；Stage 是根据依赖关系切分出的执行阶段；Task 是一个 stage 中针对一个 partition 的具体执行实例。

### Q3：配置参数为什么会影响性能？

分区数、资源容器数量、CPU 和内存会影响并行度、任务排队、网络传输、Shuffle 数据量和 GC 压力。合理配置必须结合数据规模和分布，而不是盲目增加资源。

### Q4：为什么 Spark 的 task 会共享内存？

因为多个 task 通常以线程形式运行在同一个 Executor JVM 中。这样减少了进程启动开销，但也让缓存、Shuffle、用户对象和多个并发 task 共同竞争 Executor 内存。

## 11. 你需要真正记住的内容

如果时间有限，本章只记住下面六点：

1. 大数据框架解决的是数据并行、资源调度、故障恢复和可扩展性问题。
2. MapReduce 是“分治—Shuffle—聚合”的通用思想。
3. Spark 的核心抽象之一是 RDD，RDD 由多个 partition 组成。
4. Spark 根据 RDD 依赖形成 DAG，再切成 stage 和 task。
5. Driver 负责组织应用，Executor 负责执行 task。
6. Spark 的性能和稳定性核心，最终都与分区、Shuffle、内存、缓存和数据依赖有关。
