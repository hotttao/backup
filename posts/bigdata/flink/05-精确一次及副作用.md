# 第5章：精确一次及副作用

## 1. 为什么精确一次重要

流式程序会重启、重试和故障恢复。如果一个事件被重复处理或部分结果被重复写出，计费、库存、支付和统计结果都会出错。

“精确一次”通常要从整体效果理解：每条输入对最终一致结果产生一次影响，而不是简单地保证某个函数只调用一次。

## 2. 准确性与完整性

准确性关注已经处理的数据是否被正确计算；完整性关注应该到达的数据是否已经被纳入结果。水位和迟到数据主要帮助处理完整性，一致性状态和可靠输出主要帮助处理准确性。

## 3. Shuffle 中的精确一次

Shuffle 需要保证：

- 上游输出可重放或可恢复；
- 下游不会因为重试而重复累计；
- Checkpoint 与输入位置能够一致恢复；
- 分区数据和状态更新具有确定性。

## 4. 确定性

非确定性代码会破坏重放结果，例如随机数、依赖当前系统时间、调用不可重复的外部服务。需要将这类信息显式纳入事件或状态，或为副作用设计幂等键。

## 5. 源端与汇端

源端要保存消费位置和状态，使故障后能从一致位置重放；汇端要采用事务、幂等写入、两阶段提交或可去重协议，避免下游看到重复或半完成结果。

## 6. 副作用

打印日志、发送 HTTP 请求、写数据库、发消息都是副作用。即使计算状态做到精确一次，外部系统也可能因为重试收到多次请求。

```python
def idempotent_sink(event, db):
    key = event.event_id
    if db.exists(key):
        return
    db.insert(key, event.payload)
```

## 7. 性能权衡

更强的一致性通常需要 checkpoint、持久化、事务或确认协议，会增加延迟和存储开销。系统设计要明确选择：结果是否允许修订、是否允许重复、是否必须严格一次，以及故障时的恢复边界。

## 8. 本章核心

精确一次不是单个算子的属性，而是输入重放、状态一致性、计算确定性、Shuffle 恢复和输出提交共同形成的端到端语义。
