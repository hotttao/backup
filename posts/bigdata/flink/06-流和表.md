# 第6章：流和表

## 本章核心

本章把“流”和“表”放到同一个理论中理解：表是某个时刻数据的静态快照，流是这些快照随时间变化的记录。流不是只能用于实时系统；批处理本质上也会不断执行“表 → 流 → 流 → 表”的转换。

## 1. 流表二元关系

- **从流到表**：把更新流按键分组、聚合，得到随时间演化的表。
- **从表到流**：观察表的变化，把新增、修改和撤销编码为流。
- 表可以理解为“静止的数据”，流可以理解为“运动的数据”。
- 数据是否有界，与它当前以流还是表的形式存在，是两个正交维度。

数据库的追加日志就是一种流；事务日志应用到表后得到表的当前状态。物化视图则反过来通过变更日志把表的变化暴露成流。

## 2. 批处理为什么也属于流表模型

一个经典 MapReduce 作业可以拆成：

1. `MapRead`：读取表，把记录逐条变成流。
2. `Map`：逐条转换，流仍然是流。
3. `MapWrite`：按键分组并持久化，流变成表。
4. `ReduceRead`：再次读取表并转成流。
5. `Reduce`：逐条或逐组转换，仍产生流。
6. `ReduceWrite`：再次分组写出，流变成表。

所以“批处理”和“流处理”的关键差异不是数据是否经过流，而是输入是否结束、触发频率以及对延迟、吞吐和成本的取舍。

## 3. 四个问题如何映射到流和表

- **定义 What**：转换；非分组操作通常是流到流，分组操作通常是流到表。
- **位置 Where**：窗口；窗口把事件时间加入分组键，使同一个业务键在不同时间范围内独立聚合。
- **时机 When**：触发器 + 水位；触发器把表中的中间状态物化为输出流。
- **方法 How**：累积模式；决定多次输出是增量、完整值，还是完整值加撤销。

### 三种操作类型

| 操作 | 含义 | 典型例子 |
|---|---|---|
| 流 → 流 | 不分组，逐条处理 | filter、map、parse |
| 流 → 表 | 分组，使数据静止 | group by、join、sum |
| 表 → 流 | 逆分组，观察状态变化 | trigger、变更日志 |

“表 → 表”不是独立的基本操作：表的修改必须通过变更流，再重新分组回表。

## 4. 对 Flink 的启发

Flink 的 keyed state、窗口聚合和 changelog 输出，都可以用这套语言理解：数据进入算子后形成按 key 维护的表状态，事件时间、水位和触发策略决定何时把状态以追加、更新或撤销记录的形式发出。

## 一句话总结

流描述变化，表描述状态；分组把流变成表，触发把表的变化变成流，批流统一在同一个流表模型中。
