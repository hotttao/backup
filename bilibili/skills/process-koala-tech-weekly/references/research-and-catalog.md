# 联网核验与文章规范

## 从字幕提取工具

完整阅读 SRT，把连续字幕按主题合并为片段。对每个疑似项目执行：

1. 记录开始介绍的秒数。
2. 保留 ASR 拼写作为搜索线索，但不能直接作为最终名称。
3. 提取公司、语言、平台、模型大小、特色功能、协议或仓库所有者等辨识线索。
4. 把客观功能描述与 Koala 的主观评价分开。
5. 合并同一项目的重复提及。

第一遍提取后再检查一次遗漏。视频标题通常只列重点，不代表本期的全部工具。

## 每个条目必须单独联网核验

对每个新条目分别搜索。禁止把猜测的 ASR 名称直接写入文章。

使用当前 Agent 能够搜索和打开权威来源的任意联网机制。缺少某个特定搜索服务、浏览器集成、GitHub CLI 或 API 客户端时，只要其他能力能取得相同证据，就不能把它视为阻塞；反过来，也不能因为常用工具不可用而降低证据标准。

来源优先级：

1. 项目或厂商官方账号下的仓库。
2. 官方官网或官方文档。
3. 官方模型登记页面，例如厂商自己的 Hugging Face 组织。
4. 没有官方发布历史时，采用作者首发记录证明初次公开日期。
5. 可信第三方来源只能用于寻找线索；存在官方来源时不能把第三方页面当作最终项目地址。

至少使用字幕中的两个匹配线索确认身份，例如“功能 + 厂商”“平台 + 模型”或“项目名 + 特色功能”。

对 GitHub 项目，优先使用仓库元数据或 release/tag 历史确定日期。对于没有明确版本的项目，可以使用仓库 `created_at` 作为首次公开日期，但必须在 `lookup_notes` 中说明。

没有公开 GitHub 仓库时：

- `project_url` 使用官网；
- `project_date_source_url` 使用官方或作者发布记录；
- 在 `lookup_notes` 写明“未发现公开 GitHub 仓库”；
- 禁止编造仓库 URL。

## 确定发布时间

`发布时间` 指项目或视频所介绍版本的公开日期，绝不是 Koala 视频发布日期。

- 视频介绍具体版本或模型：使用该版本的官方发布日期。
- 新上线的服务或工具：使用官方上线日期或作者最早发布记录。
- 长期存在且没有版本的仓库：使用仓库首次创建/公开日期。
- 只查到月份或年份：继续搜索，禁止自行补出日期。

统一使用 ISO 格式 `YYYY-MM-DD`。即使日期证据地址与项目地址相同，也要在数据库中单独保存。

## 撰写 Koala 评价

评价只能来自本地字幕。

- 忠实保留观点方向：称赞、批评、限制、权衡、适用对象或预测。
- 简洁转述，不要大段复制字幕。
- 禁止添加星级、Agent 自己的判断、流行度或网上评论。
- 如果 Koala 只介绍功能，填写 `仅作功能介绍，未给出明确评价。`
- 字幕本身存在不确定性时，转述也要明确保留不确定性。

## 按主要用途分类

分类前先读取 `posts/tool/anything.md` 的现有标题。优先选择符合工具主要用途的现有分类，禁止只根据实现语言分类。

当前分类示例：

- 备份与数据保护
- 终端与桌面 UI
- 代码质量与 Code Review
- Web 与 JavaScript 开发
- 测试与质量保障
- 运维、部署与基础设施
- AI 模型与推理
- AI Agent 与智能体开发
- 数据工程与存储
- 协作与项目管理
- 多媒体与图形

只有全部现有分类都不合适时，才创建简洁的新标题，并放到概念相近的分类附近。每个工具或具体版本只能保留一条规范记录。

## 维护文章表格

每个分类必须使用以下固定表头：

```markdown
| 工具名称 | 作用 | 发布时间 | Koala 给予的评价 | Koala 视频 | GitHub / 项目地址 |
| --- | --- | --- | --- | --- | --- |
```

行格式：

```markdown
| Tool Name | 一句话作用 | 2026-07-31 | Koala 对该工具的评价转述。 | [BV... · 00:09](https://www.bilibili.com/video/BV...?t=9) | [GitHub](https://github.com/owner/repo) |
```

具体规则：

- 单元格中禁止出现 `|`，包括转义形式；校验脚本会严格统计列数。
- 使用核验后的官方名称；确认名称后移除“按字幕转写”等临时标签。
- 一小时以内使用 `MM:SS`，超过一小时使用 `HH:MM:SS`。
- `?t=` 使用工具片段开始时的整数秒。
- 最后一列根据来源标记为 `GitHub`、`官网`、`项目文档` 或 `Hugging Face`。
- 禁止用搜索结果或新闻报道代替最终项目链接。
- 保留当前视频范围外的旧条目。
- 必要时同步调整文章说明，确保其中对 `发布时间` 的定义与本规范一致。

## 最终内容检查

提交前确认：

- 每个提取出的项目都有一行文章记录和一条数据库缓存；
- 所有缓存条目的 `lookup_status` 都是 `verified`；
- 每个新增行都包含本期 BVID 和时间点；
- 每个新增行都有官方项目 URL；
- 每个日期都有持久化保存的证据 URL；
- 找到官方拼写后不再保留错误 ASR 名称；
- 没有新增重复条目；
- 每个数据行恰好六列。
